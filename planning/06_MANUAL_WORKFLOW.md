# Manual Workflow

## Режим работы

Проект сейчас ведётся вручную.

Перед каждым этапом нужно получить пошаговую инструкцию и выполнять её строго по шагам.

## Что делать перед изменениями

Перед любым этапом выполнить:

```powershell
git status --short
```

Если есть неожиданные изменения — остановиться и разобраться.

## Что запрещено без отдельного разрешения

Нельзя без отдельного разрешения:

- запускать heavy wrappers;
- запускать quick-quality;
- запускать fresh/cached tuning;
- менять базу данных;
- чистить reports;
- удалять артефакты;
- делать git commit;
- делать git reset;
- делать git clean;
- менять label policy;
- менять class weights;
- менять training objective.

## Как выполнять этап

Каждый этап должен иметь:

- номер;
- цель;
- список изменяемых файлов;
- команды проверки;
- ожидаемый результат;
- список данных, которые нужно прислать на анализ.

## Что присылать после этапа

После выполнения этапа прислать:

```powershell
git status --short
```

Если менялись файлы:

```powershell
git diff -- <file_path>
```

Если запускались тесты:

```powershell
python -m pytest <test_path>
```

Также прислать:

- какие файлы созданы;
- какие файлы изменены;
- какие команды прошли;
- какие ошибки были;
- итоговый вывод терминала.

## Правило planning/

В `planning/` нельзя складывать:

- `.py` файлы;
- временные scripts;
- snapshots;
- run outputs;
- ZIP archives;
- diagnostic payloads.

Для этого есть другие папки или внешний backup.

`planning/` — только для планов, статуса, текущей задачи и книг.
