The recovery archive was moved on the same volume only after the recovery
processes, Readonly API and PostgreSQL container were stopped. PostgreSQL and
Readonly were then recreated with the new bind mounts. The old host path no
longer exists. PostgreSQL's internal `pg_wal` remains part of its managed
PGDATA volume; it is database storage, not the host recovery archive, and was
not split out of PGDATA.

The controlled restart acceptance terminated only the command-line-verified
supervisor and worker processes. The installed Windows task started a new
generation, drained to zero backlog, and republished WAL and PITR as READY.
LIVE remained disabled throughout.
