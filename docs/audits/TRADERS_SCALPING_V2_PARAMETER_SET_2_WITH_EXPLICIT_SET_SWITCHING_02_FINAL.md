## Switching semantics and evidence

The resumed source-level call-path review supersedes the initial blanket PASS:
the boundary resolver had only been tested directly while the pipeline used
startup globals. The correction binds the real PipelineRunner to one atomic
configuration read per boundary, pins all symbols/retries to it, and passes
RR/risk/target/EV values from that same snapshot to evaluation. Financial
reporting now partitions by persisted set identity (legacy IDs remain separate).
The new metadata fields are excluded from the legacy 15m semantic identity,
which was compared directly with pre-task commit 47f05b4. PAPER operator is
also an affected consumer and was deployed alongside pipeline and readonly.
All three OCI revision labels equal c5176c0ba87ee0e3395ceb0b0bf09b5a1a7e5429.
Portfolio admission consumes the immutable runtime snapshot carried by the
actual PipelineResult, including the original cycle's risk-per-trade value.
The cache pins seven days of supported cycle/retry boundaries. Configuration
replacement/deployment is operator-managed; no writable Desktop/API selector
or uncontrolled environment fallback was introduced. Switching across process
restarts uses the persisted cutoff; this is not a multi-revision switch ledger.
Rollback must set previous_parameter_set to the outgoing set, active_parameter_set
to Set #1 and the next boundary/revision, then deploy affected consumers together.

The YAML selector is the only authority. A boundary strictly below
`1788885600000` resolves the immutable Set #1 snapshot; a boundary equal to or
above it resolves the immutable Set #2 snapshot. Rollback consists only of
changing `active_parameter_set` to `scalping-v2-set-1` and recording the next
cutoff/revision. There is no Python, environment, Desktop, or database fallback
selector.

The first configured cutoff was corrected during production acceptance to the
first boundary actually processed by the deployed Set #2 runtime. PostgreSQL
then proved 16,250 pre-cutoff rows with zero Set #2 rebinding and 70/70 rows in
the first seven post-cutoff boundaries with the Set #2 ID and semantic hash. No
open position existed at activation; lifecycle tests additionally prove that
persisted entry identity is not reinterpreted.

The exact two-config replay used the same frozen dataset, market paths, cost
inputs, evaluator, and chronological portfolio engine. Set #2 produced a
nonzero eligible cohort and materially smaller loss/drawdown in this bounded
sample, but remained loss-making. This is an interim PAPER experiment, not an
optimal, profitable, or LIVE parameter promotion.
