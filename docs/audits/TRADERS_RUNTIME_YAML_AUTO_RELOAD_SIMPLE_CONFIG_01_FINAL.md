## Real acceptance

The one-time refactor deployment used images built from clean commit
`d2dbc70bace89d7231ac4b9e8186bb1957d4fea0`. After deployment, a host save
changed the active Set #2 RR from `0.458508` to `0.459508`. The container saw
the new file immediately, validation created a pending generation, and boundary
`1789428000000` persisted ten completed runtime rows with exactly one generation
and the new RR. No container ID or restart count changed.

The value was restored by another ordinary save. Boundary `1789428300000`
persisted ten completed rows at generation `1789428229078626900`, all with RR
`0.458508`. Runtime, Readonly API, and operator config managers reported the
same generation/set/hash. The Traders Funnel after F5 displayed the same final
Set #2 and resolved hash without a desktop restart.

The desktop fallback followed `docs/desktop_automation_policy.md`: PID 4516,
HWND 10421362, same session/WinSta0/Default desktop, compatible integrity,
responsive foreground window, and full-desktop cropped capture all passed.
The native Computer Use app binding was unavailable, so the policy-authorized
PID/HWND Win32 fallback was used for read-only Funnel navigation and F5.

The separate project-wide legacy source-scan still contains pre-existing
failures unrelated to this change (removed historical `trade-5m-v1` expectations
and an old server-source `binance` token prohibition). They were not hidden or
reclassified as hot-reload failures.
